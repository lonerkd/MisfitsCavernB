# Audit — 2026-11-07: what was built 3–7 November, against the rules

Requested by the owner: review everything done in the past four days for poor
effort or execution, "cheap fakes", mocks, and anything not in line with what
came before, because much of it was done through a weaker (local) model.

**Method.** (1) Scanned every *added* line of the 172 source files changed since
the Paper-default work (`0be16fda`..the open PR #427's branch) for fakes, mocks,
simulated work, swallowed errors, `as any`, hard-coded colours, direct database
calls from components, `localStorage`, `alert`/`confirm`. (2) Compared the 26 new
production views against each other and against the features they sit beside.
(3) Read the largest pieces in full. (4) Built PR #427 and ran the editor,
Studio, reports and accessibility specs against it. (5) Checked the new
migrations against `database-and-security.md` and the rules in `RULES.md`.

**What this is not.** It is not a line-by-line read of all 172 files. Not
reviewed in detail: #410–#413 (small fixes and docs), the scripts/decoder
internals, and the open PRs #425, #404, #346, #331, #330. Findings are marked
**verified** (seen in code or run) or **suspected** (a pattern that needs a look).

## Verdict in one paragraph

The work is uneven. The **mood boards (#424)**, the **Weather view**, the
**shot list**, the island, and the stats/shortcuts/Community work meet the rules
(tests at the right level, RLS through the helpers, errors reported, tokens, no
`as any`). The **26 production views merged in #423** do not: nineteen are the
same ~100-line component copy-pasted, they save into one JSON blob with no error
handling, no tests, no docs, free-text scene and character names (the opposite
of the film-graph direction), and on `main` today **17 of them cannot take their
first record**. Open PR **#427** fixes most of that but ships a default theme
that fails WCAG AA on nearly every page, a "removed" editor sidebar that is
still in the file behind `false &&`, and a security hole that has already been
fixed on its branch.

## What is good (so the rest is read in proportion)

- **Mood boards (#424):** RLS on both tables through `can_access_project`, indexed foreign keys, no `as any`, no hard-coded colours, deletes through `useConfirm`, unit + integration (Sam, Jordan, Riley) + e2e tests, docs. This is the standard.
- **`WeatherView`** calls the real Open-Meteo forecast and derives its risk flags from the response: no fake data. **`ShotListView`** reads the real `shots` table through the Studio context. **Safety, Catering, Shot list, Production report** handle failures with a toast.
- **Island (#418, #428), stats (#419), shortcuts (#422), Community (#402):** tested at the right level, persona-tested where data is touched, reviewed in a Claude session.

## What to do, in order

1. **Do not merge #427 as it stands.** Its CI is green because PR CI does not run the specs that fail.
2. **Theme (H2):** keep the owner's decision to make Misfit the default but lift the accent to pass AA (candidate `#ee3a0c`), or keep Paper the default. Then run `accessibility.spec.ts` and `npm run theme:scan` for it.
3. **Editor (H3):** delete the `false &&` block; make the navigator reachable and update `editor-keyboard-reorder.spec.ts` to the new place; run all `editor-*` specs.
4. **Views (H1, H4, M1):** one shared `useSettingsList(key)` (typed key, the atomic RPC, error toast, empty state with the form) replacing the 19 copies; delete confirmations through `useConfirm`; remove the `as any`.
5. **Storage (M2, H4):** decide whether the role views are owner-only or for the crew. If for the crew they need real per-record tables with RLS (`can_access_project` / `can_shape_project`), linked to scenes and characters by id and to the media library, persona-tested: a design decision for the owner, not a wider write to project settings.
6. **Duplicates (M3):** `DoodView` should call `dayOutOfDays()`; `RevisionsView` should read the real revisions; check the suspected overlaps before building more role views.
7. **Verification (M4):** a test per view at least for "first record can be added" and "a failed save shows an error"; one e2e that adds a record in a view; docs in `studio-and-preproduction.md` and the bible.
8. **Process:** run `accessibility.spec.ts` and the editor specs on any PR that touches the theme or the editor (they are nightly-only today); a PR's title must name what it contains.
