# Session - 2026-11-18: fewer Vercel deployments (the owner decided to cut volume)

The free plan allows 100 deployments a day and was hit again today (every push to a branch with a pull request is one; many parallel sessions and batched pushes). The owner chose to cut deployment volume rather than move to Pro. **What changed:** `vercel.json`'s `ignoreCommand` is now `scripts/vercel-ignore.sh`. The old one-liner looked only at the tip commit and skipped only markdown, notes and workflows. The script looks at everything since the branch's last deployment (`VERCEL_GIT_PREVIOUS_SHA`, falling back to the fork point or the parent) and builds only if a file that goes into the app changed. **Newly skipped:** `e2e/`, `tests/`, `*.test.*`, `supabase/` (migrations, config, the schema snapshot: the app imports none of it), the dev scripts (except `scripts/preview-env-guard`, which `next.config.js` requires), the lint, size and mobile baselines, and `dependabot/*` branches (CI judges a version bump). `main` always builds. **A bug fixed on the way:** a push of several commits whose last one was a note used to be skipped even when an earlier commit changed the app; it now builds. `scripts/vercel-ignore.test.mjs` checks nine cases against a throwaway git repo (the multi-commit case included). **Not verified:** on Vercel itself (the cap is hit today, so no build runs to observe; `VERCEL_GIT_PREVIOUS_SHA` is documented but unseen here); the first pushes after the cap resets will show it. The one-push-per-PR habit still matters (RULES 9, STATE 2b).
