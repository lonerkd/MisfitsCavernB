# Session — 2026-11-08: Caps Lock + P — the keys now choose from the project list

Owner: after Caps Lock + P you could not select a project with the keys. **Cause:** `onDeckKey` toggled the list open but never gave it any keys: the digits 1–9 jumped to the nth app (navigating away), the arrows moved through the island's own controls, and Enter acted on whichever control had focus. **Fix:** while the project list is open its keys are the list's: Down/Right and Up/Left move a highlighted row (it opens on the active project), Enter picks it, 1–9 pick that row and the list closes; Escape still closes it. The rows show their number and a one-line hint ("↑↓ choose · Enter opens · 1–9 picks"), the list is a real `listbox` with `option` rows and `aria-selected`. **Verified:** `e2e/island-projects-keys.spec.ts` (three projects; arrows + Enter pick and the island's project button names the pick; a number picks without changing the page; Escape closes) passes on a fresh build against the local stack. **Not verified:** a physical Caps Lock (the spec dispatches the key events with the lock flag, as the other island specs do), a phone (no keyboard layer there).
