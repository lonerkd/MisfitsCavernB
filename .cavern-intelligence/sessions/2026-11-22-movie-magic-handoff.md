# Session - 2026-11-22: Movie Magic handoff, first slice (3.54, gap 1)

Interchange with the industry standard by the documented way in, with no writer for a proprietary binary format. No migration.

**(a) FDX for Movie Magic Scheduling.** `scriptToFdx` now writes each Scene Heading with `Number="..."` (the writer's typed `#12A#` numbers, taken out of the heading text; a script with none gets 1, 2, 3 and an XML comment `<!--cavern:autonumbered-->` so a re-import does not turn them into typed numbers) and `<SceneProperties Length="1 3/8" Title=""/>` (page eighths, as Final Draft writes it). `parseFdx` reads `Number` back into `#N#`, so a Final Draft file's numbers survive import. Tests: `lib/scriptos/fdx-export.test.ts` (parses the XML, numbers, lengths, escaping, round trip), the existing round-trip suite still passes.
**Breakdown tags were not written.** Movie Magic Scheduling's import page says element tags arrive from the tagged `.sex` file Final Draft's Tagger exports; an `.fdx` brings headings and speaking characters. The `TagData` / `TagNumber` layout is not in any source I could read (one GitHub issue lists names, marks it as unconfirmed). Writing a guess risked a file Final Draft rejects for no gain, so it is the left-over: a `.sex` writer once its format can be confirmed from a real file. Not read: Final Draft's own FDX documentation (none public).

**(b) Excel budget.** An **Excel** button beside Print / PDF and CSV on Studio › Production › Money (`PrintButton` takes an optional `excel` prop; no other tool changed) downloads `budget-<project>.xml`: SpreadsheetML 2003, which Excel and Numbers open, built in `lib/studio/budget-sheet.ts`. Chosen over a hand-built `.xlsx` because no zip writer exists in `lib/` and SpreadsheetML needs no dependency (RULES 9) and no binary code to get wrong. Layout: account / category / description / planned / committed / paid / left, above the line and below the line (one flat group when none is above), a total per category and per group, rows for spend on no line and approved labour, a grand total taken from `moneySummary` (the screen's own numbers). Numbers are real numbers; text starting `= + - @` gets a leading apostrophe, markup is escaped, control characters dropped. Account numbers are ours (1100, 1200 ... above; 2100 ... below), not Movie Magic's chart of accounts.

**Verified:** `npm run typecheck`; eslint on the changed files (0 problems; a whole-repo lint was not run); `npx vitest run lib components` (3418 pass); `e2e/budget-excel.spec.ts` and `e2e/budget-lines.spec.ts` against the local stack both pass (5s and 6s).
**Not verified:** nobody has opened these files in Movie Magic Scheduling, Final Draft, Excel or Numbers on a real machine. Whether Movie Magic takes the scene numbers and lengths from the `.fdx`, and whether Excel opens the `.xml` without a warning, is unknown; the `SceneProperties` attribute set is from memory of Final Draft files, not a spec.
