**Root cause, from the full code review:** the stale sprint handler was one case of a general bug — `usePillStage` republished a descriptor only when its labels or fields changed, so *every* page's action handlers stayed frozen at an old render. `usePillStage` now publishes stable wrappers that call the newest handler (`withLiveHandlers`, `lib/os/PillContext.tsx`, tested), so the editor needs no ref and no page can be stale. Also fixed from that review: the Undo tile reads the undo scope from the router's pathname, not `window.location` (which can lag a client-side navigation); the Studio action is labelled *Share tab* (it goes where the Share tab goes, lock screen included); the editor's sprint is one action whose key the coverage reference now shows correctly (`I`).
