# Session - 2026-11-13: the nightly e2e, red for twelve nights

The scheduled `e2e-local` failed every night from 2026-11-02 to 2026-11-13 (all five shards; 11 specs of about 190). It was not one cause. Each was read from the CI logs and reproduced against a real local stack (a production build, the committed migrations, a real browser) before it was fixed.

**1. A real accessibility bug (the biggest).** The print kit's buttons (2026-11-08) carried an `aria-label` that did not contain their visible text ("Print / PDF", "CSV"), and the phone editor's bar button was labelled "Scripts and scenes" while showing the script's title. Axe's `label-content-name-mismatch` (WCAG 2.5.3) fails any page with one: continuity, documents, daylight, money and the all-pages accessibility sweep. The names now start with the visible text (`Print / PDF: <tool>`, `CSV: <tool>`, `Scripts and scenes: <title>`); a unit test keeps the print buttons' names containing their text. The e2e nightly is the only place the axe sweep runs, which is why nothing on a PR caught it.

**2. A real product bug: "Read X as a character again" did not stick.** Rejecting a name writes a private `reading_memory` row (a trigger); removing the correction never removed it, so after a reload the person's own memory still rejected the name, here and in their other scripts, while the toast said it would be read normally. Fixed with an `AFTER DELETE` trigger (`internal.reading_memory_forget_correction`, migration `20261113000000`, counts down only the acting person's own row) and the editor re-reads the memory when a correction is removed. Persona test added (counts down, removes at zero, a crew member's delete does not reach another person's memory).

**3. Specs that no longer matched the product** (the product was right): portfolio pieces are private by default since 2026-11-08, so three specs that made a piece without a visibility never saw it (`share-pages`, `real-data`, `accessibility`); the Locations header shows its progress as a progress bar, not the sentence "0 of 2 locked down" (`locations`); the Music section loads when it nears the screen, so `home-music` scrolls it into view.

**4. A flaky locator.** `getByLabel('Script', { exact: true })` (32 uses, 19 specs) sometimes matched two textareas: Next streams the page inside a hidden element and swaps it in, so for a moment the DOM holds a hidden copy. `getByRole('textbox', ...)` ignores hidden elements. This was the open "second element labelled Script" item in the backlog.
