# Session — 2026-11-01: ad export (C4) — a piece or the whole campaign as text or PDF

Campaign deliverables (Studio, behind `ad_copywriting`) now has a **Text** and a **PDF** button on every piece and **Export all** for the set. What is exported is the piece's working text as the editor holds it now, with the type, where its latest review version stands ("Draft", "Sent to client", "Client approved"…), characters and spoken time against its limits (and by how much it is over), and its notes. The PDF is one piece per page with the campaign name above the title and a page number below; a long piece runs onto more pages. Layout is pure (`lib/ad/export.ts`); jsPDF loads only when a PDF is asked for (`lib/ad/exportPdf.ts`), so the page weight is unchanged (every page still within budget).

**Limit, said to the person:** jsPDF's built-in fonts hold Western European text only, so other characters print as "?" in the PDF and a toast says so; the plain-text export keeps every character.

**Verified:** 11 unit tests for the layout, text, file names and the PDF-safety rules; 4 for the PDF itself (a page per piece, page numbers, a long piece paginates, unsupported characters, an empty set); 4 component tests for the panel (a real file is handed to the browser with the piece's text, status and limits; the whole set; a PDF with the "?" notice; a failed export says so). I rendered a sample PDF and looked at it. Typecheck, lint, 1871 unit tests, build and the bundle budget are clean. `e2e/ad-export.spec.ts` (local stack, a real browser): an Advertising project with two copy pieces, the Share tab, a piece as text, the whole set as text and a piece as a PDF each download with the real copy in them (1/1). **Not verified:** the PDF in viewers other than poppler, and the toast about unprintable characters in a real browser (only in the component test).

**Copilot's review (3 findings, all real, fixed):** the export now reads the device's copy of a script first when it holds unsynced edits or the network is down (as the editor opens it), falling back to the server's; the review status is read fresh when an export starts (a failed read shows an error instead of printing "Draft"); and the "characters shown as ?" notice now covers everything the PDF prints, the campaign name included. Not done: reading the editor's React state directly (the Studio is a different page; the editor saves to the device first, but typing in the last two seconds before leaving the editor is not saved by it, an older limit).
