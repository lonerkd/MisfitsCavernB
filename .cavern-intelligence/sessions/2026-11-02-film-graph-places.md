# Session — 2026-11-02: places read through the film graph (cutover step 3)

A scene's place was read by matching heading text everywhere (`locationKey(scene.location)`), even though the database already links `scenes.location_id` to `project_locations`. Now one resolver (`lib/film/places.ts`, `placeResolver`) answers "where does this scene shoot": the linked location's current name, else the heading's text. The stripboard (strips, company-move marker, locations per day), the auto-scheduler (`packShootDays`, new optional `placeFor`), the call sheet's day locations and addresses, readiness (its check and the "lock down" list) and the Locations list all read through it. Defaults are unchanged, so nothing that does not pass a resolver behaves differently.

**What this makes possible:** a location can be renamed (Studio › Locations › Name, `renameLocation`; a name already in use is refused with a message). Every scene linked to it follows, in every tool above. The script's headings keep their words; a heading edited afterwards files under whatever name it spells.

**Verified:** 6 unit tests (`lib/film/places.test.ts`: link beats heading, fallback when unlinked or the link is gone, the board counts one place for two headings, the Locations list groups under the record, readiness reads the record's permit through the link, the scheduler keeps a linked place together); a real browser (`e2e/location-rename.spec.ts`: rename KITCHEN to Diner in the Locations list; the row is DINER with its scene, KITCHEN does not come back as a second row, the scene still points at the renamed record, and the same after a reload); typecheck, lint. No migration (the trigger that keeps `location_id` in step already exists).

**Not done (audit step 3 leftovers):** the public `/call/[id]` page and the call-sheet scene query still read text; `scene-sync.ts` still writes `scenes.location`. Next in the audit: calls and castings by `character_id`, then shoot days by `shoot_day_id`.

**Known limits (from review):** a rename changes the record only. If the script is re-synced and a scene is inserted again with the old heading, the link trigger finds no record of that name and makes a fresh one, so the old name can reappear as a second row; making the rename durable against that needs an alias on the record (the writer, `scene-sync.ts`, goes in the last cutover step). Call-sheet day locations print in the record's upper case (headings are normally upper case already). The e2e checks the Locations list; the stripboard, call sheet and readiness wiring is covered by the unit tests of their pure functions and the type system, not a browser.
