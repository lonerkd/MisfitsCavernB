# Session — 2026-11-02: the co-writing mis-placement, diagnosed (not yet fixed)

The nightly's `editor-cowriting` "typing at the very same spot" flake is real mis-placement of typed characters, not a slow poll. Instrumented the editor's remote-apply, caret-restore and change handlers, looped the spec until it failed (1 in ~4), and read both windows' logs: one writer's first keystrokes arrived with the caret at the end of the text although the test had placed it at the spot moments earlier. The placed caret was lost to a value re-assignment (React puts a textarea's caret at the end when it sets `value`) by a state update with no caret mapping. Details and the fix direction are in BACKLOG 3.33. The instrumentation and the temporary spec were removed before this note; no code changed.
