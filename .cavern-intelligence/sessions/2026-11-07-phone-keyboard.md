# Session — 2026-11-07: the phone experience, slice 3 — the keyboard on every page

iOS never shrinks the layout viewport for the keyboard, so a field near the bottom ends up under it and the page cannot scroll far enough. `components/phone/PhoneKeyboard.tsx` (mounted in `ClientShell`) fixes that for every page: while the keyboard is up it sets `html[data-typing]` (the island and the editor's floating tools hide on it) and `--kb` (the page's scroll area takes it as bottom padding, `globals.css`), and when a field takes focus it waits for the keyboard to finish rising and scrolls the field to the middle of what is visible (`scrollToReveal`, tested). The editor no longer sets the attribute itself (`usePhoneLayout` is pure). `scripts/mobile-audit.mjs` now fakes `visualViewport` like the specs instead of shrinking the window (which never looked like a keyboard to the app): keyboard-hides-field flags went from 8 (landscape Studio, Profile, Settings, Jobs) to 0; one false positive remains (Jobs' empty-state button is not the field's action). `e2e/phone-keyboard.spec.ts`: on Settings, in both orientations, the last field ends above the faked keyboard and the page unmarks itself when it goes. **Not verified:** a real iPhone (Safari's own scrolling when a field takes focus; the autofill bar; split keyboards).
