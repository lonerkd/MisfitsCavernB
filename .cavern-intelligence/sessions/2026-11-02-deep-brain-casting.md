# Session — 2026-11-02: the deep brain, round two: cues by layout and casing, and the cast made honest

The same method as the last round (scripts written by hand in conventions the generator does not produce, every line labelled before the engine saw it), aimed at layout and casing: an indented `.txt` screenplay, colon-style cues, plain title-case cues. And one new independent check on every hand-written script: **the cast found** (who a reader would say speaks, nobody missed, nobody invented), because the cast is what the Studio is built from.

**What held:** the indented text script (cues and dialogue placed by spaces) read correctly with no change.

**Title-case cues were invisible.** `Maya` over `Did you eat?` read as action, so a script written that way had no speakers. The document profile now learns it (`preScanTitleCaseCues` in `lib/scriptos/parser.ts`): a short, unpunctuated, title-case line after a blank, with speech under it, that **recurs** is a cue, and so is a name that sits once between two that recur (the other half of an exchange). A lone word ("Silence") proves nothing and time words are excluded. Their names are held in capitals like every other cue.

**The cast was not what the reading says.** It was the pre-scan's list, and the pre-scan takes any caps line with a sentence under it, so in a script with no blank lines caps action ("THE DOOR EXPLODES.") entered the cast: **about one invented name per script** on the blank-free surface (REAL_WORLD 1.03, INTERNATIONAL 1.17, shouting 0.87). The opposite error too: a cue whose only line is shouted in capitals was read as a cue on its line but missing from the cast. Now the cast is the names the decoder read as cues, plus the names the project already knows. Measured on the same 30 seeded scripts per style: invented names on the blank-free surface **1.03 → 0.03, 1.17 → 0, 0.87 → 0, 0.33 → 0.07**; recall never lower and higher in the cells that had misses (shouting text 0.957 → 1.000, INTERNATIONAL blank-free 0.899 → 0.992, non-Latin blank-free 0.728 → 0.939); conventional cells unchanged. A third, smaller fidelity fix: numbered extras keep their `#` (`COP #1`, not `COP 1`).

**What I got wrong on the way:** I assumed the inline `HOST: speech` form was a cast gap and wrote a test for it. It is not the decoder's: that form is the podcast format's way of writing (BACKLOG 3.35), and the format decides (a screenplay reads it as action; the podcast format finds both speakers). The test now says exactly that. A first version of the cast filter also carried a term for inline speakers that could never fire; removed.

**Verified:** the three new hand-written scripts and 7 cast checks; 14 focused tests (`profile-b4.test.ts`); cast floors in the ratchet (every cell: recall ≥ 0.99, invented ≤ 0.01; the blank-free surface: recall ≥ 0.98, invented ≤ 0.1); mutation checks (without the cast rule, the caps-action test and the REAL_WORLD and INTERNATIONAL floors fail; without the title-case rule, five tests fail); typecheck, lint, 1963 unit tests, build and bundle budget clean. **Not verified:** any real script (the private corpus is still empty), and the Studio and editor in a browser with a title-case script (only the reader changed; no UI).

**What changes for people:** a script written with title-case cues now has speakers, scenes and a breakdown; a script with no blank lines no longer lists caps action as a character; a numbered extra keeps its `#` in the cast. **Left (BACKLOG 3.21):** the rest of B4, B7, B8, B9; real scripts for `.private-corpus/` (owner).
