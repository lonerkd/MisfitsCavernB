# Session — 2026-11-02: the plan for the island at every size

The owner asked for the island to be designed for under 760 px too (many non-phone devices are that narrow), as a true extension of the tools, with the keyboard, the pointer and the island designed together for the whole screen. Checked the code: the island's brain is already surface-agnostic (modes decided from signals, a React-free activity store, `useOnSet` shared), and the size switch is two CSS lines that swap the dock for a thinner pill. The plan (`plans/2026-11-02-island-at-every-size.md`) recommends one core with three presentations chosen by capability not width, four layers the same at every size, a zone map per surface class, never stripping a tool to fit the pill, and an order that starts with a compact dock for narrow non-touch windows. It ends with four decisions only the owner can make. No code changed.
