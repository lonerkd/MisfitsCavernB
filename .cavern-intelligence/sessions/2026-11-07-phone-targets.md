# Session — 2026-11-07: the phone experience, slice 2 — touch targets and the editor's spec

`scripts/mobile-audit.mjs` found 13–100 controls smaller than a thumb per page (a project page: 97). One block in `app/globals.css` under `@media (pointer: coarse)`: buttons, tabs, selects and menu items at least 44 pt (`!important`, so a screen's own compact height cannot win on a phone — an inline `minHeight: 32` on the Lounge's "+" had to be raised by hand), inputs at 16 px (iOS zooms the page into anything smaller), bigger checkboxes, and every link gets a tappable area that reaches past its text (a `::after`, no layout change; `:where()` so it never overrides a screen's own `position`). The audit counts that area. Result: small targets 97 → 0 on a project page and 0 on most pages. The Studio's tab row shrank labels into each other once the tabs grew (`flex: 0 0 auto` now; the row scrolls and snaps). `e2e/phone-editor.spec.ts` (new): at 393×852 and 852×393 the four doors fit and are 44 pt, each opens its sheet, Escape closes it, and with a faked keyboard the element strip sits above it, the island is hidden and one tap inserts an element; `e2e/mobile.spec.ts` now checks the More sheet instead of the desk Export button. **Still flagged by the audit:** the keyboard hides the focused field in landscape on Studio, Profile, Settings and Jobs (forms: BACKLOG 3.41). **Not verified:** a real iPhone.
