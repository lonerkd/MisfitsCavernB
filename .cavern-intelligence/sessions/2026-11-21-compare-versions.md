# Session - 2026-11-21: comparing versions, slice 1 (BACKLOG 4.12)

A Compare view existed (a scene list and a line-for-line pane over `lib/scriptos/version-diff.ts`); it paired scenes by heading only, so a reordered scene read as cut and added and a renamed character as a wall of dialogue edits. This replaces it, reusing the entry point (the Revisions panel's Compare button, the editor's already-loaded revisions) and the `diff` package.

**Built.** `lib/scriptos/compare.ts` (pure): scenes paired by heading, then by content; a **moved** scene is not cut and added; a **rename** (a cue that changes the same way throughout) is one entry and the lines that differ only by the name are not changes; blank lines and scene numbers are never changes; numbers for scenes, dialogue / action / heading lines, words and pages; the filter; `changeRefs` for next / previous; `groupScenes` and `collapseRows` for the folding. `components/editor/CompareVersions.tsx`: A and B with a swap, side by side aligned by scene (stacked A over B in a full-height sheet under 760 px), `+` / `−` marks with strike and underline, "N unchanged lines" and "N unchanged scenes" folds, next / previous (buttons, N and P, focus moves to the change, a polite live region says "Change 3 of 12: ..."), a loading state and the "only one version so far" empty state, a toast if a comparison throws, and the change report through the print kit (`lib/studio/compare-print.ts`, Print / PDF and CSV, a sample in `print-samples.test.ts`). The editor's Compare button now shows with no revision too, so the empty state is reachable. `version-diff.ts` and its test are removed (nothing else used them).

**Decisions.** Lines are typed by structure in `compare.ts`, not by `parseScript`: the parser with its decoder takes about 150 ms for a 120-page script and a comparison reads two, against a 200 ms budget. The versions are the locked revisions plus the draft; `script_versions` is in the schema and nothing writes it, so no migration was needed or made. Nothing new is stored.
