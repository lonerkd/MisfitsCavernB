# Session - 2026-11-17: Next.js 16.4.6 (owner: "yes to the Next.js upgrade")

`next build` and `next dev` printed a known-vulnerability notice (and sometimes stopped on it) on the cloud container, whose `node_modules` held Next 16.4.3 while `package.json` and the lockfile already asked for `^16.4.5`. Moved to the current patch release: `next` and `eslint-config-next` to `^16.4.6`, lockfile limited to the twelve Next packages (`next`, `@next/env`, `@next/eslint-plugin-next`, the nine `@next/swc-*` binaries): npm on this machine drops the `libc` fields from the platform packages, so the lockfile was rebuilt from `main`'s with only those entries changed (`libc` kept; BACKLOG 3.1's warning about this).

**Verified on 16.4.6:** `npm ci` from the committed lockfile, `tsc --noEmit`, the whole unit suite (3,073 passed, 2 skipped), and `next build --webpack` with no security notice. Not run: the browser specs. A deployment is the real test of the Vercel build.

**Note for sessions:** a cloud container's `node_modules` can be older than the lockfile; run `npm ci` at the start of a session that builds.
