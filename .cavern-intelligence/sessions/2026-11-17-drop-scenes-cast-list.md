# Session - 2026-11-17: scenes.cast_list is dropped (BACKLOG 3.18 e, owner's yes)

The cast of a scene is its links now; no cast text is stored. `scenes.cast_list` was not a plain duplicate (the first plan said it was): the trigger `internal.scenes_link_cast` turned it into `scene_characters` and `characters_rename` rewrote it, so the drop moved the linking into the one writer. Migration `20261117200000_drop_scenes_cast_list.sql`:
- `sync_script_scenes` links each scene's cast from the same payload key (`cast_list`, the script reader's cue): names upper-cased, at most 200 characters, characters created when new, links not in the cue removed, and only when the set of names changed (so a no-op sync still writes nothing);
- `characters_rename` no longer rewrites scene text (the links follow the character by id; castings and calls still get the new name);
- the trigger and its function go, then the column.

App: `castOfScene` reads the links only (no text fallback); the stripboard, readiness, the call sheet, Today's director glance and the scene-sync plan no longer read text; `planSceneSync` compares the script's cue to the linked names (`IndexedScene.cast`, loaded by `syncScriptScenes`), so a cast-only edit still reaches the server. The demo seed writes characters and links. Tests: the persona tests that wrote `cast_list` now write through `sync_script_scenes` or link characters (`tests/integration/support/project.ts` `linkCast`, `addSceneWithCast`; `e2e/support/cast.ts`); the historical characters-backfill test went with the column; one new check that the column is gone.
