# Session - 2026-11-19: rename a character from the editor (BACKLOG 3.18 d, rung E4)

The first text-rewriting operation the editor plan asked for. Script › Character Report now has **Rename…** on each character. It (1) renames the `characters` row (so castings and call-sheet calls follow by id through the existing database trigger), then (2) rewrites every cue of that character (`MAYA`, `MAYA (V.O.)`, `@Maya`, a dual-dialogue `^`) as **one edit through the shared text** (`setContent`, which the Yjs layer diffs into a single transaction), so a co-writer typing at the same time merges with it and the next scene sync keeps the new name instead of recreating the old one (the bug the plan's section 2.1 named). Pure helpers in `lib/scriptos/rename.ts` (`renameCue`, `renameCharacterInText`, `validCharacterName`), the row half in `lib/film/rename-character.ts`.

**Decisions (mine):** only cues are rewritten, not the name inside action lines or dialogue (prose); renaming onto an existing character is refused with a sentence (merging two characters is a different operation, not built); the row is renamed before the text so the sync meets the new name already in the graph.

**Verified:** typecheck, lint, unit tests (`lib/scriptos/rename.test.ts`: cue forms, whole-name matching, round trip through the parser, name validation), and `e2e/character-rename.spec.ts` on a production build on the local stack: the cues, the character row (same id), the casting and the old name not coming back after the sync; a taken name refused; a second window typing at the end while the first renames, both survive. `e2e/editor-cowriting.spec.ts` and `e2e/editor-gutter.spec.ts` still pass. **Not verified:** a rename made while offline (the row write is online-only; the text edit would queue, so the two could disagree until reconnect: the offline queue for row writes is E4's other half, still open); a phone.
