# Session — 2026-11-01: the island holds what is running (live activities, slice 1)

`lib/island/activities.ts` is the engine: the code that owns a piece of work registers an activity (`useActivity`) and it clears itself; a pure `rankActivities` decides which one the island shows (calls and recordings, then uploads and sync, then timers, music, notices), and "+N" shows the next. `islandMode()` gains an `activity` mode (below a pointer on a page zone, above rest). First two owners: the editor's offline queue (`syncActivity`, held on every page by `useSyncActivity`: "1 script saved on this device", or "waiting to sync · retry in 12 s" with **Sync now**, or "Can't reach the server…") and the writing sprint (`sprintActivity`: time left and words, with Pause / Resume / Reset on the island; a paused sprint stays held, in amber). The island's own condition chip still says "Offline"; the activity says what is waiting. A typing dot takes the activity's tone.

**Found by running it in a browser, fixed:** pointing at an activity's button opened the island into its deck and the apps landed where the button had been; and focusing it by keyboard counted as engaging the island and pulled it away. Now a pointer that is moving, or on a button, leaves the island alone; one that rests on it for 350 ms opens it as before; focus on an activity button does not engage it.
