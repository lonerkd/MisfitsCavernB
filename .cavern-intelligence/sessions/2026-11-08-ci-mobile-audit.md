# Session — 2026-11-08: the phone audit as a CI check

`scripts/mobile-audit.mjs` (an iPhone 15 Pro, portrait and landscape, 18 routes of the built app on the local stack) used to print a report and always exit 0. It now takes `--check` (exit 1 when any route is worse than `scripts/mobile-audit-baseline.json`) and `--update` (rewrite the baseline from this run). Counted per route view: elements wider than the screen, controls under a thumb, text too small, controls under a fixed bar, sideways scroll, a focused field hidden by the keyboard, its button hidden by the keyboard, a route that errored. The comparison is `scripts/mobile-audit-ratchet.mjs` (a route may not exceed its baseline; a view the baseline lacks is allowed nothing; ids in a route are normalised to `<id>`), tested in `lib/ci/mobile-audit-ratchet.test.ts` (5). `.github/workflows/mobile-audit.yml` runs it on pull requests that touch `app/`, `components/`, `lib/os/`, `lib/island/` or the audit itself (and on demand): local stack, build against it, start, audit, upload screenshots. **Baseline today** (from a real run on `main`, 36 route views): no route scrolls sideways, none has a wide element or tiny text but `/lounge`'s one; small targets: `/projects/<id>` 1 (portrait), `/lounge` 1, `/settings` 1; controls under the bar: the studio views 1–7 (portrait), `/lounge` 1; `/jobs` has the keyboard hiding "Post the first one" (both orientations). **Verified:** the audit passes against its own baseline locally (exit 0); the ratchet's failure path by unit test. **Not verified:** the workflow itself on GitHub's runner (it first runs on this PR; if the runner's timing or the build differs, the first run may need a tweak), and it is **not a required check** (make it required after it has run green on a few real PRs; with no bypass a misbehaving required check would block every merge). This is a high-risk PR (a workflow): it needs a Claude review before merge (`tools-and-access.md` §9).
